# /platform-watch — 플랫폼 정책 마감 감사 (advisory)

마감일이 박힌 플랫폼 요구사항만 추적한다. 리포트가 답할 질문은 "최신이 몇이냐"도 "무엇으로 올려야 하나"도 아니라 **"언제까지 무엇을 해야 하고, 지금 그게 됐나"**다.

- **advisory 전용.** 아무것도 막지 않는다. 코드·`package.json`·네이티브 설정·`.gitignore`를 어떤 경로로도 수정하지 않는다. 쓰기는 §5의 셋뿐이다 — 리포트 · 상태 파일 · 핸드오프 파일.
- **환각 금지 (핵심 제약).** 모든 마감일·요구사항 주장에 webfetch로 확인한 공식 문서 링크를 근거로 단다. 확인 못 한 항목은 `확인 못 함`으로 분리한다 — **추측을 사실로 쓰지 않는다.**
- **뉴스 요약기가 아니다.** 마감일 없는 일반 릴리즈 소식은 범위 밖이다.
- **셸을 호출하지 않는다.** `date`·`cat`·`ls` 포함. 파일 접근은 Read/Write/Glob 도구만. 이게 "전 호스트 지원"을 선언이 아니라 구조적 사실로 만든다.
- **항목은 목록에서 사라지지 않는다. 자리를 옮길 뿐이다.** §6의 degrade 7경로가 전부 이 원칙 하나에서 나온다.

## 0. 정체성 — 전수 감사가 정본, 상태는 표기 전용

**리포트는 매번 전수 감사다.** 재실행하면 현재 시점의 전체 목록이 다시 나온다. 상태 파일은 각 항목에 **델타 배지를 다는 용도로만** 쓰인다.

```
전수 감사 (정본)  ←  상태 파일 (표기 전용, 판정 근거 아님)
```

- **상태 fail-safe.** 상태 파일이 없거나·깨졌거나·구버전 스키마면 **전수 리포트는 정상 산출되고 델타 배지만 생략된다.** 오류로 중단하지 마라 — 정의된 degrade 경로다.
- **상태가 판정에 새어드는 통로를 막는다.** 소스 내용 검증(§2)은 자기 완결적이어야 하고, 소스 도달 실패 시 직전 스냅샷의 날짜를 폴백으로 쓰지 않는다.

## 1. 추적 대상 — 고정 enum

**`references/watch-targets.md`를 Read한다.** 추적 대상·URL·현재값 읽기 지시·항목별 임계일이 전부 거기 있다. 대상을 스킬 본문에 하드코딩하지 않는다 — 유지보수 지점을 한 곳에 모은다.

- **동일성 키 = enum 슬러그.** URL·제목은 근거 필드일 뿐 키가 아니다. 정책 페이지 개편이 마킹을 깨뜨리지 못한다.
- **임계값은 키가 아니라 필드다.** `targetSdk 36 → 37`은 새 항목이 아니라 같은 항목의 `[변경]`이다.
- **리포트 각 항목에 슬러그를 함께 출력한다** — `--target`이 내부 식별자 노출이 아니라 이미 보이는 값의 재사용이 된다.

### enum 밖 발견물

조회 중 enum에 없는 마감을 발견하면 **리포트에 반드시 싣는다.** 동일성 키가 없으므로 델타 마킹만 생략하고 `[미분류]`로 표기한다. 같은 항목이 반복 등장하면 리포트 말미에 **enum 승격 후보**로 제안한다.

### 마킹 어휘 — 3값 고정

| 마킹 | 의미 |
| --- | --- |
| `[신규]` | enum 항목이 이번에 처음 마감을 가짐 |
| `[변경]` | 임계값·날짜 등 필드가 움직임 — **이전값→현재값 병기** |
| `[미분류]` | enum 밖 발견물 — 키 없음 |

**변화 없는 항목은 마킹 없이 그대로 나온다.** 4번째 어휘를 늘리지 마라 — 어휘가 늘면 마킹의 신호 대 잡음이 무너진다.

## 2. 소스 도달 — 2단 URL

**조용한 실패가 가장 위험하다.** fetch 실패로 항목이 리포트에서 빠지면 사용자는 "마감이 없어졌다"고 읽는다.

- **"1차 실패"에 내용 실패를 포함한다.** HTTP 200이어도 그 페이지에서 해당 항목이 요구하는 재료(임계값·날짜 문구)를 못 찾으면 실패로 취급하고 2차로 넘어간다. **리다이렉트로 무관한 페이지를 받아 거기서 아무 숫자나 읽는 것이 이 스킬의 최악 실패다.**
- **내용 검증은 자기 완결적이어야 한다** — "이 페이지에 이 항목의 재료가 있는가"만 본다. **이전 스냅샷과 비교하지 않는다.**
- **둘 다 실패하면**: 웹검색으로 새 URL 후보를 찾되(상한 = `url_candidate_limit`) **자동 채택하지 않는다.** `URL 이동 의심: <후보>`로 리포트에 올려 사용자가 참조 파일을 고치게 한다. **후보에서 값을 읽어 리포트 본문에 쓰는 것은 금지한다** — 후보는 주소일 뿐 근거가 아니다. 판정은 후보 유무와 무관하게 `확인 못 함 (소스 도달 실패)`다.

## 3. 날짜 신뢰 모델

**스킬은 날짜를 만들지 않는다.** 인용 가능한 것만 날짜로 인정한다.

| 원문 형태 | 표시 | D-day | 정렬 키 |
| --- | --- | --- | --- |
| 일 단위 (`"August 31, 2026"`) | `D-113` | 계산 | 그 날짜 |
| 월·분기 단위 (`"starting April 2026"`) | 원문 그대로 `2026년 4월` | 미계산 | **그 기간의 초일** |
| 규칙 표현 (`"one year after …"`) | 원문 인용 | 미계산 | 정렬 축 밖 |
| 날짜 언급 없음 / 소스 도달 실패 | — | 미계산 | 정렬 축 밖 |

- **정렬·표시·D-day는 세 축이다.** 한 필드로 뭉치지 마라.
- **저정밀 날짜의 정렬 기준은 초일이다.** 말일 기준이면 최대 29일 낙관 편향이 생겨 확정 마감보다 뒤로 밀린다 — **마감 추적에서 낙관 편향은 단방향 손해다.**
- 허용되는 유일한 산술은 `오늘 − 인용된 절대 날짜`다. **오늘은 컨텍스트 현재 날짜에서 온다** — `date`를 호출하지 않는다.
- **규칙 표현을 해석해 추정 날짜를 만들지 않는다.**

## 4. 현재값 읽기 · 등급

### 복잡도 상한 — enum이 요구하는 값만

"네이티브 설정을 읽는다"는 무한하지만 "enum 항목이 요구하는 값만 읽는다"는 유한하다. 초기 기준 7개 남짓 — 항목별 읽기 지시는 `references/watch-targets.md`에 있다. **전반 파싱이 아니다.**

- 경로 탐색에 `Glob`을 쓴다. `PrivacyInfo.xcprivacy` 같은 항목은 **존재 여부가 곧 현재값**이라 탐색 없이는 부재와 못 찾음을 구분할 수 없다.
- **충돌하면 해석하지 않고 모두 병기한다**(경로별로 나열). 충족 여부 판정은 **가장 낮은 값 기준**이다 — §3의 낙관 편향 금지와 동형.
- **product flavor 분기는 읽되 어느 flavor가 프로덕션인지 판정하지 않는다.**
- **경로가 전부 부재해도 항목을 빼지 않는다.** 마감은 그대로 표시하고 충족 여부만 `현재값 확인 못 함`으로 둔다.

### 등급 = f(D-day, 충족 여부) — 순수 함수

| 등급 | 조건 |
| --- | --- |
| 🔴 | 미충족 · D-day ≤ 임계일 |
| 🟠 | 미충족 · D-day > 임계일 (또는 저정밀 초일 기준) |
| ✅ | 이미 충족 |
| ⚠ | 어느 축이든 확인 못 함 |

- 임계일은 `../../shared/constants.md`의 `grade_threshold_days`에서 온다(항목별 덮어쓰기는 참조 파일). **본문에 숫자를 적지 마라.**
- 이모지는 **스캔용 시각 보조**일 뿐 새 정보를 넣지 않는다. 독립 판정이 아니다.
- 🟡·⚪는 날짜 축에서 의미가 없어 쓰지 않는다.

## 5. 산출물 — 리포트 · 상태 · 핸드오프

**`references/report-format.md`를 Read해서 그대로 따른다.** 조회가 끝난 뒤에만 열면 된다. 리포트 4블록 구조·핸드오프 스키마·경로·보존 규칙이 거기 있다.

세 파일 외의 쓰기는 없다:

```
.rn-upgrade-kit/platform-watch/reports/YYYY-MM-DD.md
.rn-upgrade-kit/platform-watch/state.json
.rn-upgrade-kit/handoff/platform-requirements.md   ← 경로는 shared/constants.md의 handoff_path
```

## 6. degrade — 7경로

**원칙: 항목은 목록에서 사라지지 않는다. 자리를 옮길 뿐이다.**

| # | 조건 | 결과 | 위치 |
| - | --- | --- | --- |
| 1 | 상태 파일 없음·깨짐·구스키마 | 델타 배지만 생략, 전수 리포트 정상 | 제자리 |
| 2 | enum 밖 발견물 | `[미분류]` + 승격 후보 제안 | 제자리 |
| 3 | 날짜 저정밀·규칙 표현·미확인 | D-day 미계산, 원문 인용 + 근거 링크 | 블록 2 (⚠) |
| 4 | 현재값 경로 전부 부재 | 마감은 표시, 충족 여부만 확인 못 함 | 블록 2 (⚠) |
| 5 | 소스 1차·2차 모두 실패 | `확인 못 함 (소스 도달 실패)` + 이동 의심 후보 | 블록 2 (⚠) |
| 6 | 사용자 스코프 제외 | `미조회 (사용자 지정 스코프)` | 블록 4 (별도) |
| 7 | 스코프 제외 항목의 **파일 반영** | 이전 값 보존 + `stale: <날짜>` | 파일 (§5) |

3·4·5는 같은 블록에 가되 **사용자가 할 일로 갈라 적는다** — `마감일 확인 못 함`(참조 파일 수리) / `현재값 확인 못 함`(프로젝트 설정 확인). **6은 ⚠와 절대 섞지 마라** — ⚠는 할 일이 있는 상태고 미조회는 없다.

## 7. 스코프 인자 — 좁히기 전용

`--platform android|ios` · `--target <슬러그>`

- **기본값은 항상 전체다. 넓히는 방향의 인자는 두지 않는다.**
- 제외된 항목은 조용히 빠지지 않고 블록 4에 남는다. 전수 계약은 *"목록에서 안 사라진다"*로 유지되고 **조회만** 생략된다.
- **두 인자를 동시에 주면 AND(교집합)다.** 공집합이면 빈 리포트가 아니라 `지정 스코프에 해당 항목 없음` + **유효한 슬러그 목록**을 낸다.
- `--platform` 필터는 참조 파일의 `platform` 필드를 읽는다. **슬러그 접두사에서 추론하지 마라** — `play/*`가 안 풀린다.
- **좁힌 실행은 상태·핸드오프를 덮어쓰지 않고 병합한다** (§5·degrade 7). 조회된 항목만 갱신하고 미조회 항목은 이전 값 + `stale`을 유지한다.
- **인자는 이 둘로 닫는다.** `--since`·`--format`·`--json`은 범위 밖이다.

## 8. 병렬화

조회 대상이 7개 남짓이라 `Agent`로 분담할 수 있다. 각 서브에이전트 프롬프트에 **반드시** 넣는다:

- **read-only 못박기**: "네이티브 설정·소스를 수정하지 마라. 파일 수정 도구와 쓰기 명령 금지. 조회 결과만 반환하라."
- **조회 범위 잠금**: "너는 오직 `<슬러그>`만 조회한다. 다른 항목은 무시하라."
- **반환 형식**: `[슬러그] 요구: <값> | 원문 날짜 문구: "<인용>" | 근거: <링크>` 한 줄씩. 실패·불명확은 `확인 못 함: <슬러그> — <사유>`로 분리. 근거 링크 없는 주장은 반환 금지.
- **판정 금지**: 등급·충족 여부·날짜 정밀도 판정은 **메인 몫이다.** 서브에이전트는 관측만 올린다.

## 실행 원칙

서두 불릿(advisory · 환각 금지 · 셸 미호출 · 항목 미소멸)이 정본 — 여기 재진술하지 않는다.

- **RN 하한을 산정하지 않는다.** 산정 재료(릴리즈 노트·registry·peer)가 이 스킬에는 설계상 없다 — 재료 없는 쪽의 판정은 추측이다. 번역은 `currency`가 한다.
- **전 호스트 지원.** Windows에서도 정상 실행되고 **iOS 항목도 판정한다** — `Podfile`·`project.pbxproj`·`xcconfig`는 repo 안 텍스트라 Xcode 없이 읽힌다. **판정 가능한 것과 빌드 가능한 것은 별개다.**
- 다음 실행 시점을 정할 때만 `references/cadence.md`를 Read한다.
