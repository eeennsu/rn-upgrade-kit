### 2. `shared/constants.md` 도달 실패에 degrade가 없다

`skills/currency/SKILL.md:111` 등이 상수를 상대경로로 Read한다:

```
경로는 `../../shared/constants.md`의 `handoff_path`.
```

상대경로는 **사용자 RN 프로젝트 CWD 기준**으로 풀리지 스킬 파일 위치 기준이 아니다. 플러그인 스킬은 호출 시 base directory를 받지만, **Read가 그 기준으로 푼다는 보장이 명세 어디에도 없다.**

문제는 어느 쪽으로 풀리느냐가 아니다:

> **degrade 경로(currency 10 · platform-watch 7 · rehearsal 없음) 어디에도 "constants 읽기 실패"가 없다.**

읽기가 실패하면 에이전트는 `report_retention_n`·`soak_minor_days`·`grade_threshold_days`를 **지어낸다.** `shared/constants.md:3`이 존재 이유로 못박은 *"한쪽만 바뀌는 드리프트"*가 정확히 그 자리에서 일어난다.

참고로 `references/*.md`의 `../../../shared/constants.md`는 파일 위치 기준으로는 올바르게 계산돼 있다 — 경로 산술은 맞다. 깨지는 건 해석 기준이지 산술이 아니다.

## HIGH

### 3. `watch-targets.md`가 자기 스키마 규칙을 위반한다

`skills/platform-watch/references/watch-targets.md:13` (항목 스키마 · `2차 URL` 필드):

> **여러 항목이 같은 2차 URL을 공유하지 않는다** — 공유하면 페이지 하나가 죽을 때 항목 여럿의 이중화가 동시에 사라져 요건이 막으려던 것이 그대로 일어난다

같은 파일의 실제 항목:

| 슬러그 | 1차 | 2차 |
| --- | --- | --- |
| `ios/min-deployment-target` (:41-42) | `developer.apple.com/news/upcoming-requirements/` | `developer.apple.com/support/xcode/` |
| `ios/min-xcode` (:49-50) | `developer.apple.com/support/xcode/` | `developer.apple.com/news/upcoming-requirements/` |

**같은 두 URL을 맞바꾼 것뿐이다.** 한쪽 페이지가 죽으면 두 항목의 2단 이중화가 동시에 사라진다 — 규칙이 막으려던 것 그 자체다.

초기 목록 7개 중 2개가 이미 위반이고, `:81`이 *"URL을 실측해 고칠 때도 지켜야 한다"*고 경고한 바로 그 실패다. Apple이 단일 호스트 공급자라 "다른 호스트" 요건을 못 쓰는 건 스키마가 이미 인정했으나(`:13`), 그 예외의 조건이 *"다른 성격의 페이지 + 항목 간 비공유"*인데 **비공유 쪽이 안 지켜졌다.**

### 4. currency "전 호스트" 주장이 셸 전제에 물려 있다

`skills/currency/SKILL.md:80`:

> **`node`는 새 의존이 아니다** — 대상이 RN 프로젝트이므로 항상 있다. 호스트·PM 무관, **Windows Git Bash에서도 돈다.**

조건절이다 — Git Bash가 셸일 때만. Claude Code의 Windows 기본 셸은 PowerShell이고, `:72-77`의 **여러 줄 큰따옴표 `node -e`**는 PowerShell 인용 규칙에서 깨진다(내부 `'` · `=>` · 개행).

`README.md:50`은 이 조건을 지우고 단언한다:

> **`currency`: 전 호스트 — 조회·파일 읽기 + registry 조회용 `node -e` 한 줄.**

**실패 시 조용히 열화된다:** degrade 9(`node -e` 실패)로 떨어져 **모든 대상이 `⚠ 숙성 미확인`** — soak·churn 게이트 2개가 통째로 죽고 리포트는 정상 산출된 것처럼 보인다. `README.md:44`의 호스트 매트릭스가 `currency: Windows ✅`인 한 사용자는 이걸 열화로 읽지 않는다.

### 5. rehearsal에 base 선택·dirty tree 처리가 없다

`skills/rehearsal/references/report-format.md:67`:

```sh
git worktree add /tmp/rn-rehearsal-0.83.4 a3f9c21
```

`a3f9c21`이 어디서 오는지 **명세 어디에도 없다.** HEAD인지, 사용자 지정인지, 브랜치 tip인지.

더 큰 구멍: **uncommitted 변경이 있을 때가 정의 안 됐다.** `git worktree add`는 커밋된 것만 가져간다. 사용자 작업 트리에 변경이 있으면 리허설은 **사용자가 가진 적 없는 트리를 검증한다.** `SKILL.md:33` 실행 거부 3종(존재하지 않는 버전 · 프리릴리즈 · lockstep 누락)에 dirty 검사가 없다.

`SKILL.md:13`이 정의한 이 스킬의 질문:

> "우리 프로젝트에서 이 업그레이드를 시도했을 때 **어디까지 갔고 어디서 멈췄나**"

그 "우리 프로젝트"가 조용히 다른 트리다. `SKILL.md:188` base 신선도 절은 이 누수를 **미래 방향으로만** 막는다(검증 후 쌓인 커밋). **과거 방향 — 커밋 안 된 현재 — 은 안 막는다.**

### 6. WebFetch 신뢰 모델이 두 스킬에서 반대다

`skills/currency/SKILL.md:65-67`이 실측으로 못박는다:

> **WebFetch는 작은 모델이 요약해 돌려준다.** 실측에서 그 모델이 ms 타임스탬프를 1년 5개월 틀리게 변환했다

그런데 `skills/rehearsal/SKILL.md:39`는 **같은 채널로 실행 거부 게이트를 판정한다**:

> 각 인자가 registry에 **존재하는 버전**인가 (`registry.npmjs.org/<pkg>/<ver>` — 404면 부재)

rehearsal은 `allowed-tools`에 `Bash`가 있는데도 안 쓴다. 자매 스킬이 "이 채널은 못 믿는다"고 실측으로 결론 낸 것을 게이트 판정에 쓴다.

- 거짓 404 → 존재하는 버전을 거부
- 거짓 200 → 없는 버전으로 리허설 시작 (T1 설치 단계에서야 깨진다)

### 7. 좁힌 첫 실행의 핸드오프 필드 부재가 미정의다

`skills/currency/references/report-format.md:77`은 **파일이 통째로 없을 때만** 표기를 정의한다:

> 핸드오프가 없으면 값을 비우지 말고 사유를 병기한다: `targetSdk — (핸드오프 없음)`

`platform-watch --platform ios`를 **처음** 돌리면 파일은 존재하고 `android/target-sdk` 섹션만 없다. 이 상태의 표기가 없다.

`skills/platform-watch/references/report-format.md:146`의 병합 규칙:

> **좁힌 실행은 병합한다.** 미조회 항목을 삭제하거나 값을 비우지 마라

이건 **보존할 이전 값이 있을 때만** 성립한다. 첫 실행엔 없다. `currency`는 `current`를 *"유일한 공급원"*(`:154`)으로 삼으므로 대체 경로도 없다.

### 8. `allowed-tools` 구분자가 규격과 다를 가능성

세 스킬 전부 공백 구분:

```yaml
allowed-tools: Read Write Glob Bash WebFetch Agent Skill
```

설치된 플러그인 캐시 표본에서 콤마 구분이 압도적이고(`Read, Write, Edit, Bash, Grep, Glob` 등), 공백 구분은 ecc `videodb` 한 스킬뿐이다.

단일 토큰으로 파싱되면 도구 제한이 통째로 무효화된다. 그러면 `skills/currency/SKILL.md:248`의 설계가 사문화된다:

> **웹 검색을 쓰지 않는다.** `allowed-tools`에 `WebSearch`가 없다 — "최신이 몇이냐"를 검색으로 찾지 않는다는 규칙을 **도구 목록으로 강제한다.**

강제 수단이 파싱에 달려 있는데 파싱이 미검증이다. `Agent`·`Skill`이 유효 도구명인지도 미확인이다(구버전은 `Task`).

### 14. 산출물 쓰기 실패 degrade 부재

세 스킬 전부 `.rn-upgrade-kit/` 쓰기 실패(권한·read-only FS·디스크 참)가 없다.

`platform-watch`가 특히 위험하다 — 쓰기가 셋인데(리포트 · state · 핸드오프) **원자성도 순서도 없다.** 리포트 쓰기 성공 + 핸드오프 쓰기 실패면 `currency`가 **낡은 하한을 현재 값으로 읽는다.** `currency`는 신선도 임계값을 두지 않기로 결정했으므로(`SKILL.md:119`) 이걸 감지할 수단이 없다.

### 15. monorepo·프로토콜 버전 미처리

`currency`는 `package.json` 단수를 전제한다(`SKILL.md:37`). degrade 10경로 어디에도 없는 것:

- workspace 루트/패키지에 `package.json` 여러 개
- `workspace:*` · `catalog:` 버전 표기
- `dependencies`가 비었거나 부재
- dist-tags에 `latest` 부재

degrade 10(lockfile)이 설치 버전 축만 덮고 선언 축은 안 덮는다.

| 10 | 환경 전제·타임아웃 부재 | **반영** | 탐지 규칙 표 + 단계 타임아웃 상수 4종 |
| 11 | 채택 게이트 3 사후 감사 | **반영** | `베이스라인:` 필드를 리포트 + **채택 커밋 메시지**에 |
| 12 | worktree 경로 하드코딩 | **반영** | `worktree_path_template` 상수 + 기존 디렉토리 처리 |
| 13 | T3 스크린샷 방법 | **반영** | 커맨드·1장·`boot_survival_seconds` 생존 확인 직후 |

## 감사가 어긋난 곳

### #3 — 규칙 위반이 아니라 규칙 사각지대였다

스키마의 문자 규칙은 *"여러 항목이 **같은 2차 URL**을 공유하지 않는다"*다. 감사 시점에 7항목의 2차 URL은 **전부 유니크했다** — 위반이 아니다.

실제로 남아 있던 건 다른 모양이다: `ios/min-deployment-target`의 1차가 `ios/min-xcode`의 2차이고 그 역도 성립하는 **교차 배치**. 한 페이지가 죽으면 두 항목이 동시에 예비 소스를 잃지만 **둘 다 도달은 되므로 degrade 5도 안 탄다.** 규칙이 막으려던 피해가 규칙 문면이 안 덮는 경로로 남은 것이다.

*"위반"으로 적혀 있으면 고칠 대상이 데이터로 보인다.* 실제로 고쳐야 했던 건 **규칙 문면**이었고, 그래서 반영은 데이터 재배치가 아니라 **스키마에 강도 3단계와 `교차` 필드를 넣는 것**이 됐다.

### #4 — PowerShell 인용 진단은 실행으로 기각됐다

감사는 *"실제 Windows 실행 1회로 확정/기각된다"*고 적었다. **돌렸다.**

Windows 11 · PowerShell 5.1 · Git Bash 양쪽에서 **한 줄 형태와 원래의 여러 줄 형태가 모두 같은 출력을 냈다.** 개행이 인용을 깨뜨린다는 근거는 없다.

남은 절반은 실재했다: `node -e`가 실패하면 **soak·churn 게이트 2개가 통째로 죽은 리포트가 정상 리포트와 겉보기에 같았다.** 그건 반영했다 — 전 대상 실패 시 헤더에 고정 문구가 박힌다. 한 줄로 고정한 것도 유지하되, **관측된 버그 수정이 아니라 셸 인자 전달에 덜 기대려는 하드닝**이라고 스킬 본문에 그대로 적었다.

## 감사에 없던 것 — 실측에서 나온 3건

### 1. 2차 URL 2개가 이미 404였다

감사는 URL 실측을 범위 밖으로 두고 *"#3은 URL 중복이라는 구조적 사실이고 페이지 생사와 무관하다"*고 적었다. 생사를 재보니:

| URL | 항목 | 결과 |
| --- | --- | --- |
| `support.google.com/googleplay/android-developer/answer/16513766` | `android/16kb-page-size` 2차 | **404** |
| `support.google.com/googleplay/android-developer/answer/13584340` | `play/billing` 2차 | **404** |

**초기 목록 7항목 중 2항목의 이중화가 이미 죽어 있었다.** 스키마를 문자 그대로 지켜도 이중화가 성립하지 않는다는 뜻이다 — 그래서 `실측` 필드가 스키마에 들어갔고, 16KB 항목은 대체 후보 2개마저 탈락해 **`2차: 없음 (사유)`**를 명시적 상태로 만들었다. 없는 이중화를 URL로 채워 가리는 것보다 낫다.

### 2. `allowed-tools`는 아무것도 막지 못한다 — #8보다 큰 문제다

감사는 *구분자 파싱*을 의심했다. 공식 문서 확인 결과 **공백·콤마·YAML 리스트가 전부 유효**하다 — 전제가 틀렸다.

대신 더 큰 게 나왔다:

> "It does not restrict which tools are available: every tool remains callable, and your permission settings still govern tools that are not listed."
> — code.claude.com/docs/en/skills «Pre-approve tools for a skill»

`allowed-tools`는 **승인 스킵**이지 제한이 아니다. 감사가 인용한 설계 문장이 통째로 명목이었다:

> *"`allowed-tools`에 `WebSearch`가 없다 — ... 규칙을 **도구 목록으로 강제한다**."*

강제한 적이 없다. **감사는 "강제 수단이 파싱에 달려 있다"고 봤는데, 실제로는 강제 수단이 애초에 없었다.** 실제 제한 필드는 `disallowed-tools`이고, 그걸 두 스킬에 넣었다:

- `platform-watch`: `disallowed-tools: Bash Edit` — *"셸을 호출하지 않는다"*가 이제 처음으로 구조적 사실이다
- `currency`: `disallowed-tools: WebSearch Edit`

다만 그 강제도 **스킬을 부른 그 턴에만** 걸린다(다음 사용자 메시지에서 풀린다). 그래서 규칙은 **두 겹으로 남겼다** — 본문의 금지 문장이 계약이고 `disallowed-tools`가 그 턴의 강제다. 필드가 생겼다고 문장을 지우면 여러 턴에 걸친 실행에서 강제가 통째로 사라진다.

### 3. `Agent`·`Skill`은 유효한 도구명이다

감사가 미확인으로 남긴 것(*"구버전은 `Task`"*). 공식 도구 레퍼런스에서 서브에이전트 기동 도구는 **`Agent`**이고 `Task*`는 세션 작업목록 관리용 별개 도구군이다. `Skill`도 유효하다. **세 스킬 모두 고칠 것이 없었다.**

## 이 반영이 남긴 한계

- **`ios/min-xcode`의 교차 1건은 못 없앴다.** Apple이 iOS 버전 요건을 두 페이지에만 싣고, 세 번째 독립 페이지 후보 4개가 실측에서 전부 탈락했다(404 또는 내용 불일치). 없는 독립성을 만들 수 없어 `교차:` 필드로 드러냈다.
- **`android/16kb-page-size`는 이중화가 없다.** 위와 같은 이유.
- **URL 실측은 도달과 내용 일치까지다.** 마감일 값 자체가 맞는지는 검증하지 않았다 — 그건 스킬이 매 실행에서 하는 일이다.
- **여전히 실행 검증이 없는 스킬이 하나 있다.** `rehearsal`은 실제 RN 프로젝트에서 한 번도 돌지 않았다. 이번에 넣은 타임아웃·환경 탐지·dirty 판정은 전부 **정적 설계**다.
